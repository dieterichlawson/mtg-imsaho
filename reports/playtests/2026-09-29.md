# Playtest 2026-09-29 — the harness, idea H19

Subject chosen from the ledger: H (the harness) had gone longest without a
night (2026-09-24, against D 09-28, G 09-27, V 09-26, L 09-25). H19 was the
only id in `harness.md` that had never been run.

H19 asks one question: **the seat collapses a menu four times; put each of
its keys beside the engine's, field for field, and for every seat-side key
that names fewer fields, find the board that makes two engine offers share
it.** #589 was one such key. Tonight found two more, plus a third defect that
the same audit turned up one level down.

and the victim in the second.

## What was filed

**#610 — the CLI keys a cast by whether there is an alternative cost, not
which one.** `llm.rs` was changed to the engine's key in 3455a85 ("a cast is
keyed by the cost it pays, not by whether there is one", #589); `cli.rs` kept
the bool, and its `position()` lookup matches the bool too, so it resolves to
the first entry. H19 guessed this was unreachable — "no card in this pool
[offers two different alternative costs], so either find one or record that it
is unreachable and say why". One does. CR 702.33 lets a graveyard card carry
several flashback instances at once and the engine implements it deliberately
(`casting.rs`, `flashback()`: "the player may pay ANY of them"). Past in
Flames grants flashback equal to the card's mana cost, which sits alongside
the printed flashback cost, so Geistflame in the graveyard is `{R}` **and**
`{3}{R}` — two entries, both `Some(_)`, one CLI row.

One save file opened twice, 4 untapped Mountains so both costs payable:

```
LLM seat                                 CLI
4: Flashback Geistflame (tap Mountain)   3: Flashback Geistflame (tap Mountain (your))
5: Flashback Geistflame (tap 4x Mountain)   — nothing —
```

**#611 — no cast row ever names a flashback cost.** The label's alt-cost note
is gated on `!cs.is_flashback`, so the tap plan is the only thing telling two
flashback costs apart — and `format_tap_plan` renders nothing when the mana is
already in the pool. Tapping Mountains one at a time at the LLM seat: `Red:3`
still shows two rows, `Red:4` shows **one**, the second having become
byte-identical and been dropped by `seen_cast_labels`. `Flashback available:`
— the one section that names a flashback cost at all — lists only the printed
`{3}{R}`; picking the surviving row took the pool `Red:4` → `Red:3`, i.e.
charged `{R}`. So at that position the prompt offers one of two legal options,
names the cost of the one it did not offer, and says nothing about the one it
did. Across 1,813 rendered flashback lines tonight, a granted flashback cost
was printed **zero** times.

**#612 — Skirsdag High Priest names the creatures it taps by card name.** It
emits one `ActivatedAbilityDef` per `C(n,2)` pair, and the pair goes into
`description` as `(tap {name_i} & {name_j})`. Two Demon tokens make two
different cost payments render as one string. Which creature is tapped is in
neither `targets` nor `sacrifice` — only in `ability_index`, decoded in
`pay_activation_cost` — so no surface can recover it. The CLI prints rows 2
and 3 byte-identical (#257's symptom from a source #257's fix does not reach);
the LLM seat groups them as `4-5: … — one per copy: 4=#37, 5=#37` on a board
holding one Skirsdag High Priest. Target is the engine, because that is where
the string is made and where one fix closes both surfaces.

## Checked, correct

- **#589's fix holds.** A forced-collision board (transformed Ulvenwald
  Mystics, native `{G}: Regenerate` at index 0, wearing Skeletal Grimace,
  granted `{B}: Regenerate` also at index 0) over 3 games and 194 collision
  boards: restricted to the menus where **both** colours were payable, the
  granted row and the native row are both present, **138 of 138**. Note the
  regenerate ability is on the *back* face (Ulvenwald Primordials), so the
  collision only exists after the werewolf transforms — worth knowing before
  building this board again.
- **`ActionRow::Copies` never names a copy that lacks the ability.** H19's
  stated regression case — three copies, one enchanted, one range `3-5` —
  holds: **328 of 328** regenerate rows named only objects that have that
  ability, and the native row correctly spans all copies including the
  enchanted one while the granted row stands alone. The key carries
  `source_card_id`, which is what makes that work.
- **Two rows with an identical label** fired 4 times in 3,048 prompts, all on
  a `ChooseCardName`-style prompt listing basic land names ("Mountain",
  "Plains"), where the options genuinely are fungible. Not the cast collapse.
- **Two *different* alternative costs from the non-flashback path are
  unreachable, and here is why:** `casting.rs:180` takes `alt_costs[0]` under
  the comment "Use the first (cheapest) alternative cost. Multiple alternative
  costs would need a chooser, but for now there's only one source at a time."
  So for a card in hand the engine emits at most one alt-cost entry per
  object, and the CLI's bool key is injective over those. The graveyard path
  is the one that escapes this, which is why #610 lives there.

## Method notes

- **A harvest tells you what is in the menu, never what is missing from it**
  (H18's note) — and the greppable substitute, "named in the board, absent
  from the rows", **does not self-clear**. The prompt states no available mana
  (H5's suspicion, confirmed), so the predicate cannot distinguish a lost row
  from an unaffordable cost: 213 raw hits, and the post-hoc filters I tried
  (colour availability inferred from the mana rows, regeneration shields) left
  177 that were mostly my own parser tripping over multi-line attachment
  notes. What worked instead was **constraining the board** so every candidate
  is affordable, and then the count is exact and boring: 138 of 138.
- **The predicate that found #612 is a good shape to keep**: a `Copies` row
  whose `— one per copy:` list names the same `#id` twice is a structural
  impossibility, needs no game knowledge, and is one line of regex. It fired
  twice in 3,048 prompts.
- **Snapshot the save from inside the stub.** `--save` is overwritten at every
  decision, so it holds the position the seat is being asked about *right
  now*. A `CLAUDE_CODE_BIN` stub that copies the save aside the first time the
  prompt matches a predicate turns "I saw this once in game 4" into a save
  file that opens the same board at any seat. Every repro filed tonight is
  built this way, and comparing the two surfaces at one save is what made
  #610 and #612 unarguable.
- **A stub policy needs a defined fallback.** Mine fell through to a random
  schema-valid answer when no row matched its ranking, which quietly spent the
  graveyard cards the probe was trying to set up; two runs were wasted before
  I noticed. Pass explicitly.
- **`--check-invariants` was on for every run and never fired**, for all three
  defects. Every invariant in the repo is engine-internal; both of the
  engine's own lists agree in each case, and nothing compares a rendered row
  against the offer it stands for. That is the same blind spot #589 recorded,
  and it has now cost three more issues.
