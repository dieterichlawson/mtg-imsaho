# Playtest night, 2026-10-31: the game

Subject: the game. R2 found no new code outside issue fixes. The only "fresh untried" ids were H32 and H37, and both had already run inside combined rows, so the rotation chose the subject. The game had gone longest without a night (2026-10-26). Its one untried id is L57, which is a watch for new card sets and has nothing to do until one lands. So the night went to the Competitor's C series, which had not run since 2026-08-29..09-08 while the engine's combat, funding and transform code changed under it. Three probes ran in parallel, each on its own tmux socket: C19 with C16, C24 with C5, and C26 with C27 and C29. That came to 21 hotseat games, all under `--check-invariants`, with no invariant violation logged.

## R1: propagation sweep (issues closed 2026-10-30)

The window was #957, #969, #970, #971 and #972.

- **#972 (auto-pass past an unseen Main Phase 1):** the "reached or gone by" stop is the same shape on all three seats that pass for someone. The CLI does it in `should_break_pass` (`TargetMainPassed`), the LLM seat in `pass_until_stop` and the page in `autoPassStop`. The draft runner and the hosted table play through the same `mtg-player` seats and page bundle, and the random seat never passes ahead.
- **#957 (observer-only decisions):** `observed_only` serves both `--stop-after` and `--decision-stats`, and `fuzz_reach.py` reads the new `observed` map. The draft runner has no decision stats. Its 50,000-action budget counts actions, not decisions, as it always has.
- **#970 (pick refusal):** the new wording uses `in_front`'s `round + 1` and `size - left + 1`, which is the page's numbering.
- **#969 (game links as paths):** seats get a path. The page resolves it, and the client resolves it against its own join link (`lobby_origin`). The host's own `cli` seat resolves it against the server's own host. The host's terminal and the "browser went away" notices keep the absolute URL, which is the right one for the person at that terminal.
- **One escape, from #971:** the drawn-game count reached the page (`matchScore`), the client (`between_listing`) and the game page's match line. It did not reach the AI seat's between-games prompt, `build_sideboard_prompt`. That prompt says "You have won 1, your opponent 0" before game 3 and names only the last game, so an earlier draw is never stated (#976).
- **Checked, correct:** the game's system prompt (`MatchFormat::match_section`) computes what's at stake from the game number as well as the wins, so a drawn game still counts toward what it says.

## C19 with C16: multi-blocks and every combat window

There were 7 games: one-off RG/BRG attackers against a mono-W defence. After two games lost to natural shuffles, the hands were re-dealt from the mulligan-point save.

- **Holds:**
  - triple and quadruple blocks;
  - lethal counting damage already marked, and deathtouch's 1;
  - over-assignment to a blocker;
  - trample excess only once every blocker has lethal, and all of it when the only blocker is removed;
  - a blocked non-trampler stays blocked when its blocker is removed (509.1h);
  - Selfless Cathar sacrificed in response, with lethal recomputed;
  - protection, and Moonmist;
  - a first-strike step created by a trick after blocks (510.4);
  - a priority window at beginning of combat, after attackers, after blockers, between the damage steps and at end of combat.
- **#982 (sev:rules):** damage among several blockers still follows the damage assignment order, where each blocker in turn needs lethal damage before the next. Current 510.1c lets the attacker divide damage freely. `docs/plans/formal-verification.md` names the divergence, but no issue tracked it. This may be deliberate, and the issue says so.
- **#983 (sev:rules):** destroying an attacker removes its blockers from combat. They lose `[BLK]`, and a first-striking blocker's damage step is not created. This mirrors #725 from the blocker's side.

## What the night taught

- A natural shuffle wastes most of a C night. Editing the save gets to a planned board on turn 1-8 and keeps the position legal: re-deal the mulligan-point save by swapping identities, or place permanents in the turn-1 save. All three probes found this on their own. It is now written into `playing.md`.
- A combat-state map has two sides. #725 fixed one of them, and #983 is the other. That gives C41.
- A demand with an X is invisible to every "can I still pay for this" check built on `greedy_autotap`, which gives C42. A transformed source named after it dies is the same bug class as last-known information, which gives L66.
