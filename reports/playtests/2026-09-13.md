# Playtest night — 2026-09-13

**Subject**: drafting (`mtg-draft-runner`), chosen from the ledger rather than
from memory. Deriving the per-subject last nights out of
`reports/playtests/LEDGER.md` gave the CLI (V/M) 09-12, the game (C/L) 09-11,
the harness (H) 09-10 and drafting (D) 09-09 — so drafting had gone longest
without a night. Reading the ids actually run out of the ledger
(`D1 D2 D3 D4 D5 D7 D9 D10`) against the ids in `docs/playtest/drafting.md`
left **D6, D8 and D11–D18 untried**; three of them were taken.

**Crew**: 3 probes. **D11** run here; **D8** and **D6** run in parallel as
subagents, each with its own capture directory under `logs/playtest/d-night/`.

**Runs**: 35 `mtg-draft-runner` runs in total — 16 for D11, 14 for D8, 5 for
D6 — plus ~30,000 synthetic tournaments driven against the `mtg-draft`
`Tournament` API directly, and 8,000+ captured LLM requests. **No metered API
seat was spawned at any point**: every run passed `--model cc` explicitly (the
flag defaults to `claude`), and every run but one drove a `CLAUDE_CODE_BIN`
stub. The exception is D11's headline run, which is a genuine `claude -p`
draft and tournament on the CLI's own login.

**Issues**: 11 filed — #480–#490.

The night's shape: **drafting is two harnesses in sequence and the second one
is where the fixes stop arriving.** Three of the four things D11 went looking
for in the tournament phase came back clean — the schema-key rule holds across
3,210 requests, session continuity holds across a seat's 42 picks and into its
deck build, and a real `cc` seat answered every prompt kind a drafted Innistrad
deck reached. What broke is the two bounds that were added to `mtg-runner` when
#462 and #399 were fixed and never added to `mtg-draft-runner`'s copy of the
same game loop. D8 and D6, working on the draft's own half, found the mirror
image: the pieces nobody has ever probed (the Swiss bookkeeping, the pick
prompt's content) are each wrong in ways that have been wrong since they were
written.

## D11 — the tournament phase on the subscription seat

**Result: #398's class is clean here too, the `cc` contract holds, and the two
watchdogs that make a mute seat survivable exist in `mtg-runner` only.**

D11 exists because D7 verified the draft's `claude -p` contract and stopped at
the last pick, on the same day the tournament phase could not cast a Skaab
Goliath at all (#398). The probe was in two halves: harvest every request
shape a drafted deck actually reaches, then take a real `cc` seat through a
draft and a tournament and audit the games.

### What held

**The schema-key rule.** 3,210 captured requests from six tournaments, swept
for the rule `mtg-player/src/llm.rs::schema_key_is_legal` asserts: **zero**
top-level property keys fail `^[a-zA-Z0-9_.-]{1,64}$`. Card names appear as
schema keys 400+ times and every one of them is nested a level down, under
`maindeck`, exactly as `call_once`'s `debug_assert` requires. The blocker
prompt's top-level keys are `"0"`, `"1"`, … which are legal. No empty enums
(the other 400 shape), largest enum 24 values, largest schema 6 top-level
properties. #398's class does not reproduce in the draft runner.

**The `cc` subprocess contract**, audited from the completed real run's captured
argv: 166 invocations (2 of them `--version` availability probes, 164 model
calls, matching the run's own usage summary exactly), **4 distinct session
ids** — one per seat for the draft
(`--session-id` once, then `--resume` 42 times — 41 remaining picks *and* the
deck build) and one per seat for the game, because `claude_code.rs::init` resets
`session_id` to `None`, so "fresh context per game" is true rather than
advertised. Calls per session: 43, 43, 55, 23 — no session leaks across a phase
or a seat. `--model` was never passed, which is correct for a bare `cc` seat,
and `ANTHROPIC_API_KEY` was unset throughout, so no metered path was reachable
even by accident. Zero `API_ERROR`, zero `API_RETRY`, zero `MALFORMED`, zero
substituted picks, zero substituted decks. The run finished `exit 0` with
Seat 0 winning 1-0 on turn 14.

**Every prompt kind it reached was answerable.** Across the stubbed tournaments
a drafted 2-seat Innistrad pod reaches 9 distinct request shapes — `pick`,
`maindeck`+`lands`, `action`, `confirm`, `mull`, `indices`, `card_indices`,
`order`, and the per-blocker assignment object. One real 14-turn game reached 6
of them plus the two draft shapes and answered all of them usably. The three it
did not reach — `confirm`, `card_indices` (the cleanup discard) and `order`
(trigger ordering) — are board-dependent, and covering them on a real seat wants
decks chosen to force them; that is the honest limit of one game, and the reason
the schema sweep above was run over 3,210 stubbed requests rather than over this
one run.

One nuance worth recording against D6's re-send measurement: the real run's
usage came back `328in / 78,339out / 4,679,649cached`. On a `cc` seat the
verbatim re-sent system prompt lands almost entirely in the CLI's prompt cache
rather than in fresh input — which is why the code calls re-sending it
"harmless", and why the cost argument against prompt size is weaker here than
the *comprehension* argument #483 and #487 make.

### What broke

**#488 — #462's progress watchdog never reached the tournament phase.**
`mtg-runner` got `STALLED_DECISIONS = 100` and a diagnostic naming the seat,
the turn and the prompt. `mtg-draft-runner::play_game` is a second copy of the
game loop and has one bound: `max_actions = 50_000`, then a silent concede.
`grep -n STALLED_DECISIONS mtg-draft-runner/src/main.rs` returns nothing. This
matters more here, not less — in a tournament *every* seat is an LLM seat.
Demonstrated: seed 101 with a seat whose array answers are all `[]` loops on
`Ghoulcaller's Chant: choose 1 target` for **2,724 identical rejections in 230
seconds**, stuck on **turn 19**, a **16 MB / 426,339-line** log, exit 124
because only the kill ended it — and **an empty stderr**, the whole time.
Five other seeds finish normally, so this needs a pool that reaches a min-1
target slot with the board frozen.

**#489 — the usage summary drops the rejection count.** #399's fix put a
`rejected` counter on `mtg_player::llm::LlmModelUsage` and the line that prints
it in `mtg-runner`. `mtg-draft-runner::print_usage_summary` copies the game
phase's usage into its own struct field by field —
`calls, input, output, cache_read, cache_create` — and `rejected` is not in the
list, so it is discarded one line before it would have been printed, next to
the standings. Observed at seeds 7, 11, 41 and 101: 2, 10, 14 and 2,724
unusable answers respectively, and in every case `exit=0` and a summary reading
`claude-code: 667 calls, … = n/a (plan quota)` with no suffix. Flagged but not
filed separately: the summary is keyed by *model*, so every `cc` seat in a pod
shares one row and even a restored counter could not say which seat was mute —
the draft half has per-seat reporting for exactly this (#195, #200) and the
tournament half has none.

**#490 — every target-set prompt numbers its options twice.**
`0: 0: Abbey Griffin`. `choose_target_set` still builds `format!("{i}: {name}")`
labels — the index was there because the label used to be the schema key and
needed to be unique — and `mark_indices` numbers the listing itself. 46
instances across the captures, all of them this one call site;
`choose_object_subset` takes its labels from `format_combat_creature_list` and
renders correctly. The doc comment above the function still describes the old
boolean-keyed schema. Cosmetic in the ordinary case, and the prompt it disfigures
is the one #488 loops on.

## D8 — tournament integrity

**Result: the parts that touch the decks are right; the Swiss bookkeeping is
wrong in four ways, none of which has ever been probed.**

14 runs at `--players` 1–7 and `--best-of` 1/2/3, plus a throwaway crate driving
the `Tournament` API over ~30,000 synthetic tournaments — which turned out to be
the cheap way to work this subject, since a pairing question that costs 90
seconds of drafting per sample costs microseconds against the library.

Held: **each seat plays its own drafted deck** (40/40 cards identical between
each seat's `## Your decklist` and its `DECK` block, in all 34 seat-games);
**play/draw** (game 1 a coin flip, then the previous game's loser on the play,
traced through a match that went to game 3); **standings arithmetic** (every
seat's printed W-L equals its logged matches plus its byes, and `total_games` is
right); and **seeded reproducibility through the tournament half** — two runs of
`--players 6 --seed 1` came back byte-identical, so #402's fix holds past the
last pick. `--players 1` is degenerate but honest and was not filed.

- **#480** — greedy pairing repeats a pairing when a rematch-free one exists.
  Round 3 of `--players 6 --seed 1` re-plays round 2's Seat 3 vs Seat 5. Of
  1,831 rounds containing a rematch in the sweep, **all 1,831 were avoidable**.
- **#482** — the bye is the pairing scan's leftover, with no bookkeeping at all.
  `--players 5 --seed 1` gives Seat 4 two of the three byes; it played one match,
  lost it, and finished 3rd. One seat gets 2+ byes in **62.4%** of 5-seat events,
  and 750 of 9,000 byes go to a seat that is not the lowest-ranked, contradicting
  `generate_pairings`' own doc comment.
- **#484** — `--best-of 2` plays **three** games (observed 2-1) while both seats'
  prompts say "Matches are best-of-2 … Games 2 to 2". Same cause — the match loop
  counts wins, not games — means a drawn game extends a match without bound and
  makes a drawn *match* unreachable, so `Standing::match_draws` is dead code. The
  draw half is reasoned from the code and labelled as such: the engine's only
  draw path is a simultaneous loss in `sba.rs` and stub-piloted ISD decks could
  not reach it.
- **#486** — a bye is indistinguishable from a won match in the standings.
  `--players 3 --seed 1` prints Seat 0 (played 2, went 1-1) and Seat 1 (played 1,
  lost it) as the same line, `1-1 (1 game wins)`. Scoring a bye as a match win is
  correct per MTR; the reporting is what is wrong.

## D6 — draft prompt sufficiency

**Result: the seat is told the shape of the draft and almost nothing about the
cards in it, and the one channel it is relied on to remember through is empty
after a resume.**

5 stub runs (2-seat, 8-seat, `--guide`, a `--resume` from a truncated snapshot,
and a reproduction run driven by a compact stub inlined into the issues), 4,765
requests captured. Measured: system prompt **44,437 B / 733 lines**, of which the
card reference is **43,772 B (98.5%)**; pick prompt **mean 218 B**. An 8-pod
draft re-sends 14.93 MB of system prompt against 72,846 B of actual pick text —
99.51% re-sent, reported here rather than filed, since it is plan quota on a
`cc` seat and the code calls it harmless.

Held: the `LEFT/RIGHT/LEFT` the prompt prints matches `DraftState::rotate_packs`
at all three pack rounds (112/112/112 prompts); pack round, pick number and pack
size are all on the header line; the card reference covers every non-basic card
that appeared in a pack; DFC pack lines resolve to reference entries on both
sides; `--guide` reaches both the draft and the tournament seats. **Schema rule 1
holds across all 4,765 captures**, including deck builds over pools containing
`Altar's Reap`, `One-Eyed Scarecrow` and DFCs.

- **#481** — the pool is restated at **2 of 42 picks** (`pick_index == 1`, so pack
  2 pick 1 and pack 3 pick 1). The other 40 picks are the pack alone, and the last
  pick of a pack is made with a pool 13 messages stale. The only other channel is
  `--resume` session memory, and `_history` is passed into `build_pick_prompt` and
  dropped. **That channel is empty after a `--resume`**: replayed picks go through
  the no-op `record_pick`, so a resumed seat's first call opens a *fresh*
  `--session-id` at "Pack 1, Pick 6" with no pool listing — both seats made nine
  consecutive picks knowing nothing about the five cards they owned, with nothing
  saying so. #401's shape on the prompt side.
- **#483** — the pack is bare names. Across 420 pick prompts, no mana cost, colour,
  type, P/T or rarity on any `Available:` line; the seat must resolve 14 names
  against entries scattered over 717 reference lines. **Rarity appears nowhere in
  the 44 KB prompt** while the rules text says "value bombs (powerful rares)" —
  and the program knows it. The game harness prints `Moon Heron {3}{U} 3/2`; this
  one prints `1: Moon Heron`. Draft-side instance of #132.
- **#485** — "seat", "players" and "pod" appear nowhere in the system prompt or in
  any of 420 pick prompts, and `## How drafting works` is **byte-identical for
  `--players 2` and `--players 8`** while describing an 8-pod. In the 2-pod the
  guide itself recommends, LEFT and RIGHT are the same neighbour, the pack wheels
  back after one pick rather than eight, and "read signals" is vacuous. Draft-side
  #115.
- **#487** — the deck-build prompt is one sentence and an `Nx Name` list: no
  colour, cost or type, no land or spell target (the only land guidance is a
  `description` string inside the JSON schema), no statement of the answer shape,
  and no mention of the sideboard the runner builds and logs. Concretely: a
  drafted basic land is keyed in **both** `maindeck.Plains` (enum `[0,1]`) and
  `lands.Plains` (unbounded), with `1x Plains` in the pool and no word on which to
  use.

Two smaller observations not worth their own issues: the last pick of every pack
is a one-card forced choice still sent as a full subprocess call (3 per seat per
draft, 24 in an 8-pod), and `"Pack 3, Pick 14 (1 cards)"` has the plural wrong.

## What the night taught the guide

Two ideas added, both from things a probe walked into rather than went looking
for: **D19** (the drawn game, which no probe has ever reached, from #484) and
**D20** (does the prompt change when the draft does, from #485 and #481).

The method note worth keeping: for a subject whose runs are minutes long, the
cheapest instrument is a `CLAUDE_CODE_BIN` stub that answers *from the schema*.
One generic stub — fill every enum by a hash of the prompt, build a legal 40-card
deck for the deck schema — takes a whole 2-seat draft and tournament from six
minutes of real model time to eight seconds, captures every prompt and schema on
the way past, and is deterministic enough that a run replays. Every finding
tonight except the `cc` contract audit came out of one.
