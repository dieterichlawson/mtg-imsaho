# Playtest night — 2026-09-10

**Subject**: the harness (the LLM interface), chosen from the ledger rather than
from memory. Last harness night was 2026-09-04, longer than any other subject
(drafting 09-09, the game and the CLI 09-08, M 09-05), and of the ten ideas in
`harness.md` exactly five had ever appeared in a ledger row: H1–H5. H6, H7, H8,
H9 and H10 had never been run.

**Crew**: 4 probes — H8, H6, H9, H10, all Handler — three of them run in
parallel as subagents on their own sockets and their own `logs/playtest/h*`
prefixes.
**Runs**: 126 games through the real `mtg-runner`, every one of them answered by
a local `CLAUDE_CODE_BIN` stub, plus 6 direct `claude -p` calls to settle what
the real CLI accepts. **No metered API seat was spawned at any point**; the only
`claude` invocations were the six schema probes, on the CLI's own login.
**Issues**: 11 filed — #455, #456, #457, #458, #459, #460, #461, #462, #463,
#464, #465, #466 — plus a measurement comment on #399.

The night's shape: **the things this subject was most afraid of have been
fixed, and what is left is a harness that cannot tell "nobody answered" from
"the answer was nothing".** #398's schema class is clean. #203's hang is gone.
#206's leak is gone. H10's motivating bug is gone. H9's headline worry — the
decision buried in an unreadable prompt — does not reproduce. Six of the
twelve issues filed are one defect wearing different clothes: a path that
substitutes a legal no-op for an answer it did not get, and says nothing.

## The four that matter

**#462 — nothing bounds the cast→cancel→recast cycle.** A seat takes
`Cast Stitched Drake (exile 1 creature from GY)`, cannot answer the
additional-cost prompt, and the engine correctly cancels the cast (CR 601.2c)
and returns priority — with the same cast on offer. Nothing counts the
repetition and nothing caps it: **2,180 cancelled casts in 60 seconds, stuck on
turn 15, 81,815 log lines, ended only by `timeout` (exit 124)**. Every
repetition of the prompt is byte-identical to the one before it (1,471 of 1,490
priority prompts in a second capture were the same string), `--check-invariants`
stays silent because every rewind is clean, and in a real `cc` game each turn of
the cycle is one subprocess call against a real login. This is the shape #398's
six lost Skaab Goliath casts would have taken with a seat that does not vary.

**#458 / #459 — the `claude -p` call still ends on EOF, and the timeout only
watches one pipe.** `call_once`'s comment says it waits "on the result, not on
EOF"; the reader thread's `tx.send` happens after `read_to_string` returns,
which needs EOF. So a well-behaved seat — valid answer, exit 0 — with one stray
grandchild pays that grandchild's whole lifetime on *every* decision: 0.88s
became 87.87s over 29 calls, and a grandchild outliving `CALL_TIMEOUT` makes the
harness discard 29 complete, correct answers and play the game mute. The
stderr half is worse: `stderr_reader.join()` has no deadline at all, so a
grandchild holding stderr reproduces #203 verbatim — wedged forever with the
answer already in hand, an empty log, zero `API_ERROR` lines — and because
`drop(group)` runs *before* that blocking join, Ctrl-C finds four zeroed
`LIVE_GROUPS` slots and orphans the tree to init.

**#463 — the cleanup discard is the only decision made with no board.** Every
other prompt goes through `build_prompt` and carries the turn, both boards, both
graveyards and the recap. `choose_card_set`'s `DiscardToHandSize` arm builds its
message from a format string instead, so the complete stdin the seat receives is
345 characters of card names. In a `ub-zombies` mirror the seat was choosing
between `Stitched Drake` (castable only if a creature is in its graveyard),
`Makeshift Mauler` (same), `Unbreathing Horde` (a 0/0 whose size *is* the
graveyard) and `Think Twice` — and the graveyard is not in the prompt. The CLI
player is looking at those panes the whole time; the random seat answers with the
first `min` cards, so the fuzzer never notices. 570 instances of this prompt in
the H8 harvest alone.

**#455 / #456 / #457 — the fuzzer's seat answers three questions with a
constant.** H10 found its own motivating bug fixed — `ChooseTargetSet` rolls
now, and Feeling of Dread genuinely names 0, 1 and 2 targets — and the identical
mistake two blocks above it, with a comment that names it: the exile-cost arm
takes `min`, which is 0 for Harvest Pyre, so **191 casts across 20 seeded games
exiled nothing and dealt no damage**, one bucket in the whole distribution. The
generalisation is that the constant need not be the minimum: "always keep" makes
the entire London mulligan unreachable (**140 mulligan decisions, 140 keeps, 0
mulls, 0 bottom lines**), and a seat that always answers with a *set* and never
with `CancelCast` makes four engine un-stash branches — each one a past bug fix,
#123, #262, #290 — unreachable to the fuzzer forever.

## What was cleared, and it is a lot

- **#398's schema class.** 4,311 structured requests harvested from 38 stubbed
  games across ten coverage decks and four one-off decks reached **9 distinct
  top-level shapes** (`action`, `card_indices`, `confirm`, `mull`,
  `attacker_indices`+`planeswalker_attacks`, the numeric-keyed blockers schema,
  `floating`/`lands`/`rocks`/`dorks`, `order`, `indices`) and **zero** keys
  failing `^[a-zA-Z0-9_.-]{1,64}$`. Both request paths are literal-keyed: the
  game's ten `send_message_structured` sites and the draft's two
  (`llm_client.rs:203`, `:247`), whose only dynamic keys (`maindeck_props`) are
  nested under `maindeck`.
- **The half no test can check: a schema the API accepts is one the model can
  answer.** Six direct `claude -p --json-schema` calls, one per shape the
  harness actually emits. All five real shapes were accepted and answered
  correctly: a **253-value integer enum** (Nevermore's "choose a nonland card
  name" offers every implemented nonland card — the largest enum in the
  program, and the index→name mapping is right there in the prompt), nested
  card-name keys with spaces, parentheses and `#`, integers expressed as string
  enums, objects with `"properties": {}` in `required`, and
  `minItems`/`maxItems` on an enum array. The control — the *same* card-name
  keys moved to the top level, which is #398 — returned
  `API Error: 400 tools.0.custom.input_schema.properties: Property keys should
  match pattern '^[a-zA-Z0-9_.-]{1,64}$'`, so the failure mode is still live and
  still detectable; the code simply no longer does it.
- **#203's hang and #206's process/workdir leak.** The never-answering
  stdout-holder now times out on schedule, kills the group, reaps the child,
  logs three `API_ERROR` lines plus `exhausted all 3 attempts`, and plays on.
  No leaked stub or `sleep` processes and no stale `/tmp/mtg-claude-code-*` after
  any completed run; `sweep_stale_workdirs` removes the one a `kill -9` leaves.
  The single exception is the stderr path (#459).
- **H9's headline worry.** The question is last and clearly delimited in **all
  3,471** captured prompts, including a 442-line one. Activated-ability rows
  carry both `(#id)` and the ability text, so two identical creatures are
  tellable apart, and `short_effect_summary`'s 200-char truncation never fired.
- **Shimmering Grotto's six mana abilities** do not become six identical rows:
  cost-bearing mana abilities are never offered. Only true duals duplicate,
  which is #460.
- **Six of nine `random.rs` arms roll properly**: the target set, the object
  set, pile division, both combat prompts, and the twelve enumerated prompts via
  the generic uniform pick.

## The seam: "nobody answered" and "the answer was nothing"

Four probes arrived at one mechanism from four directions, which is the result
worth carrying forward.

`send_with_schema` substitutes `{}` for an answer it cannot use, and each of the
ten callers turns `{}` into its own legal no-op. **Four of them log it and count
it; six do not.** `pick_action_index`, the mulligan, `choose_card_set` and
`choose_x_funding` write a `MALFORMED` line and increment the `rejected` tally
that 08c0a181 added to the run summary. `mark_indices` (so: "up to N" targets,
object sets, **exile costs**), the blockers prompt, the attackers prompt,
`choose_pile_division`, `choose_ordering` and `confirm_concede` do not — they
write a line indistinguishable from a real decision, or nothing at all.

Measured: three games in which a stub answered everything legally except the
"up to N" target set, where it returned a **successful** call whose result was a
refusal. 4 mute prompts, **0 `MALFORMED` lines, 0 `VALIDATION` lines**, a log
that says `CHOSE [P1] 0 target(s)`, and run summaries with no
`answers rejected → fallback` suffix at all. That route produces no `API_ERROR`
line either, because `call` returns `Some(json)` whenever `is_error` is false:
a model refusal, a truncated response and an answer to the wrong schema all
arrive as one shot, no retry, no error log, `{}`. A remedy for #399 that keys
off retry exhaustion would miss every one of them. This is on #399 as a
comment rather than a new issue, since it is the count that issue asked for.

#462 is what the same `{}` does to the *game* rather than to the log, #463 is
the prompt that cannot be answered well even when the seat does answer, and
#455–#457 are the same design mistake in the seat the fuzzer plays — where the
consequence is not a lost game but an oracle that has gone quiet.

## Method notes for the next harness night

- A `CLAUDE_CODE_BIN` stub that records every `(prompt, schema)` pair, validates
  the schema the way the API does, and synthesizes a legal answer from the
  schema is the cheapest instrument this subject has. 4,311 requests, nine
  shapes, no quota spent. Keep it.
- Answering with the **maximum** over the schema concedes on the first priority
  window — `Concede` is the highest `action` enum index — so a "max" policy
  never builds a board. Wide boards need a policy that reads the action labels
  (prefer `Play`/`Cast`, never `Concede`), an opponent that cannot interact
  (`60 Island`), and a self-sustaining defender.
- One site was never reached in 4,311 requests: `choose_pile_division`, which
  needs Liliana of the Veil at −6 (10 games never got her past 5 loyalty). It is
  also the one site the schema test's doc comment singles out as safe *because*
  it nests its card-name keys — so the claim nothing exercises is the claim the
  test is resting on. A direct `claude -p` probe of that shape was the
  substitute tonight; a real game reaching it is still owed.
- The enforcement of the top-level-key rule is a `debug_assert!` in
  `send_message_structured`, compiled out of the release binary the playtests
  run, and `llm_request_shape.rs` asserts the *predicate* rather than the
  schemas — its own comment says it cannot check them from there. So the rule is
  only enforced at prompts a debug-mode run actually reaches. The harvest above
  is the empirical complement.
