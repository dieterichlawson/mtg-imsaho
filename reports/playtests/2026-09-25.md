## L50 — the action menu's source label, when two permanents offer the same ability

**Negative. The hole the idea describes is already closed, on both surfaces
it names.** Nobody need pay for this again; what follows is what was
established, so the idea can be retired rather than re-run.

L50's premise is that the row is built through `perm_name`
(`mtg-player/src/cli.rs:3448`), which formats `"{name} {p}/{t}
({your|opp})"` and stops — so two clones of one creature print
byte-identical rows. `perm_name` does still stop there, but it is not the
last word: `build_action_menu` labels ability rows through
`ability_row_label`, which returns a `MenuLabel { text, ids }` carrying the
source object plus whatever slots the row already commits to, and every
render path goes through `menu_row_texts`, which finds groups of rows whose
*text* collides, works out the id positions on which the group is not
unanimous, and appends `(#id)` to each member. That machinery is #257's, and
L50 was written without it in view.

Verified at runtime rather than from the code. Seed 11, `20 Swamp / 20
Bloodline Keeper` against `40 Plains`, two Bloodline Keepers on the
battlefield and both past summoning sickness at turn 11:

```
  0: Pass priority
  1: Bloodline Keeper 3/3 (your): {T}: Create a 2/2 Vampire token with flying (#26)
  2: Bloodline Keeper 3/3 (your): {T}: Create a 2/2 Vampire token with flying (#27)
  3: Tap Swamp (your): Add {B}
  4: Concede
```

All three of L50's checks pass:

- **The rows differ.** `(#26)` / `(#27)`, appended only because they
  collided; with one Keeper summoning-sick the turn before, the single row
  carried no id at all, which is the right behaviour — an id that
  distinguishes nothing is noise.
- **Activating row N acts on the permanent row N names.** Picking row 2 put
  `Bloodline Keeper ability (#27) (you)` on the stack, and the `i`
  inspector afterwards showed `6: Bloodline Keeper 3/3 [T] (#27)` tapped
  beside `5: Bloodline Keeper 3/3 (#26)` untapped.
- **The LLM seat is not the surface with the hole.** L50 guessed `llm.rs`
  "may already be right" because `obj_name` carries the id; it is right, but
  by a different route — the ability rows there are built from `ab.name`,
  which the engine already hands over as `Name (#id)`
  (`mtg-player/src/llm.rs:4036`), and `Seed::AbilityCopy` then groups copies
  deliberately (#461) with an index per copy.

Two collapses that look like the same bug and are not, checked and correct:
four Bloodline Keepers in hand render as **one** `Cast Bloodline Keeper` row
(interchangeable — #54), and two untapped Swamps render as **one** `Tap
Swamp (your): Add {B}` row, deduped by `card_id` in the engine itself
(`mtg-engine/src/engine.rs:280`, with the comment saying so).

## L51 — the derived damage amount, as a number the player is never shown

**Two findings, and the pool's other derived-damage sources checked clean.**

Seed 23, `19 Mountain / 10 Island / 4 Mindshrieker / 3 Heretic's Punishment
/ 2 Devil's Play / 2 Harvest Pyre` against `20 Swamp / 20 Walking Corpse`.

**#590 — Mindshrieker says nothing when the milled card's mana value is 0.**
The `+X/+X` line lives inside the `if mana_value > 0` guard, so the most
common outcome of the ability — a milled land — produces a mill line and
then silence, byte-identical to an ability that resolved and did nothing.
The asymmetry shows up inside one game: three log lines later, **Devil's
Play with X=0 does say `dealt no damage`**. The CLI player can read the P/T
off the board pane; the LLM seat, which has the log and no pane, cannot.
Same class as #553 (damage) and #299 (counters), both settled the other way.

**#592 — Heretic's Punishment claims damage it did not deal.** Its own
closing line is `format!("… milled {mill_count} cards, dealt {max_mv}
damage")`, built from the amount it *requested*, with no reading of what the
damage pipeline did. Pointed at an Unbreathing Horde carrying a +1/+1
counter (seed 3, `12 Mountain / 10 Swamp / 6 Walking Corpse / 6 Unbreathing
Horde / 6 Heretic's Punishment` against `40 Plains`), the log prints the
truth and the falsehood on consecutive lines:

```
511  Unbreathing Horde (#34): 5 damage from Heretic's Punishment (#38) prevented, removed a +1/+1 counter
512  Heretic's Punishment milled 3 cards, dealt 5 damage
```

The board agrees with 511. This is #467's defect in a different card, and
L45's "general move" is what found it. A sweep of the rest of the pool for
card-written outcome lines returns eight; seven are correct (Paraselene
counts what the destroy pipeline destroyed, Mirror-Mad Phantasm branches on
found/not-found, Trepanation Blade reports what it measured), and the eighth
is **Olivia Voldaren**, whose `deals 1 damage to X, makes it a Vampire, and
gets a +1/+1 counter` asserts the damage clause without checking it. Read
only, not reproduced; recorded as a comment on #592 so the fix is to the
mechanism rather than to one card.

**Checked, correct** — the rest of L51's list:

- **Devil's Play, X=0, on flashback.** `p0 cast Devil's Play (#37)
  (flashback, X=0) targeting p1` → `Devil's Play (#37) dealt no damage to
  p1`. The card deliberately has no zero guard and reaches
  `queue_damage`'s `no_damage_line`. The stack pane carries the amount
  before resolution (`Devil's Play (#37) (X=0) (you) -> opp`), which is
  #259's fix holding.
- **Harvest Pyre.** Same `PendingEffect::DealDamage` path as Devil's Play
  and the same absence of a guard, with the comment naming CR 120.8 and
  pointing at `damage::deal_damage`. Code-verified, not played — the two
  cards are the same two lines.
- **Heretic's Punishment off a mill of three lands.** `Heretic's Punishment
  milled 3 cards, dealt 0 damage`. The 0 *is* reported — the card's own line
  covers what its `max_mv > 0` guard stops `no_damage_line` from saying.
  Reported twice, though: `mill_cards` already logged `Heretic's Punishment:
  p0 milled 3 cards` on the line above.
- **The announcement order for an X spell.** The CLI asks targets first and
  X second (`Devil's Play: select a target` → `Devil's Play (#37): choose X
  funding (0-2)`), which is the reverse of CR 601.2b/601.2c. Nothing is
  revealed between the two questions and no legal target depends on X, so
  this changes no outcome in this pool; noted rather than filed, and written
  into `playing.md` as L52 for a pool that can make it matter.

## The concede dialog (found inside L51, filed as its own issue)

**#591 — what you type at the concede confirmation is bounded by the
terminal width, not the panel.** `confirm_yn`'s `echo_cap` is
`term_w - (echo_col + 1)` where the file's other two readers use the panel
edge; the echo, and the erase that precedes each repaint, run through the
middle pane's right border and over the CARDS pane. At 150 columns the
border belongs at column 119:

```
row 27: len=120 col119='│'
row 28: len=146 col119='t'   ← the concede row, mid-echo
row 29: len=120 col119='│'
```

Reached by a mis-keyed menu number while building the L51 board, which is
how a person would reach it too. The first render of the dialog is correct;
it is the typing that breaks the frame.
