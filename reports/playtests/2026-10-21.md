## R1: propagation sweep (issues closed 2026-10-20)

**Window:** #818, #819, #820, #834, #852, #858, #859, #866 and #867, fix commits e699e27..c4b06b6. I also swept 5e52396 (a pack's last card is taken without a call), which changes what the runner and the hosted table ask.

**No escape found.** Checked, correct:
- **#834 (the LLM's trigger-order rows in the seat's words).** The page's order widget draws the engine's `options`, which `display_name_with_state` builds. They carry no "triggered by" cause, so they carry no raw `p1`. Only the CLI and the LLM build rows from `details.cause`. The CLI uses p0/p1 throughout, so `p1` is defined there.
- **#852 (a held Enter on the draft page).** `mtg-draft-client` turns an empty line into `Command::Nothing`. `add` and `drop` are set inserts and removes, so they are idempotent. A pick typed within `PICK_GRACE` of a new pack is refused. The game page's `s`/`f` toggles were covered by 778f50b.
- **#858 (the system prompts and the history window).** The draft rules' sentence comes from `history_note(history_exchanges())`, and all three draft backends set `window: history_exchanges()`. What the prompt says and what is kept agree.
- **#818 (the standings heading).** Both the client and the draft page read `standings_after`, and the fixtures carry it.
- **5e52396.** The empty-prompt branch in `draft_pick` is reached only by the AI seats' last card. The human path passes `"human"`, `auto_pick` passes its note, and the runner and the server are the only `log_draft_pick!` callers. The seat's notes are held in the client, so the pick-14 skip does not reset them.

## V59: the runner's own exits and eval flags, with a cli seat

**Why this probe.** `--stop-after` and `--decision-stats` were built for `scripts/decision-eval/` and `scripts/fuzz.sh`, and no crew had run either one. In the game loop, three things end the run with a bare `std::process::exit`:
- `--stop-after` (`main.rs:863`)
- the invariant failure (`:998`)
- the watchdog's `die` (`:913`)

Each of these skips what the normal path does after the loop, and what `quit_at_prompt` and the signal handlers each do themselves: clear the frame, unlink the snapshot, and write the stats.

**Found, #868.** `--p1 cli --p2 random --seed 7 --stop-after 2` ends on the cli seat's keep and exits 0. It leaves:
- the whole board on screen;
- the `DECISION 2 p0 "MulliganKeep"` line printed inside the frame at the cursor;
- the shell's next output painted over the board;
- `/tmp/mtg-hot-reload-<pid>.json` (pid gone, 70 KB, both hands) in /tmp until another run's sweep removes it.

The tty modes were fine: `stty -a` was identical before and after. A random-vs-random `--stop-after` run leaves no file. The invariant exit and the watchdog exit are the same code shape. I could not stage either one from outside, because `--resume` refuses a doctored save before the first frame.

**Commented on #868: `--decision-stats` is lost on the same exits.** `--stop-after 50 --decision-stats f` exits 0 with no file. `fuzz.sh` runs every game with the stats flag and `--check-invariants`, so a failing seed's game adds nothing to the reach report, and the report does not say a file is missing.

**Found, #869.** `decision_kind_name` files the keep/mulligan menu under `priority`. Seed 7 has 129 decisions by both counters, and `--stop-after 1` and `2` are both `MulliganKeep`. On seeds 1-6, three games mulliganed to 6 and none of that shows in the stats. The bottoming that follows is the generic `set_prompt`. The reach report therefore cannot show the blind spot #456 found (140 keeps in 140 mulligan decisions).

**Checked, correct:**
- **Type-ahead between back-to-back trigger prompts.** `begin_decision` keys a pass-less menu by its context line, so I set up two simultaneous Falkenrath Noble triggers: Noble blocks Bears and both die, seed 59, hotseat. The triggers ask with different headings, "Falkenrath Noble's dies trigger (...)" for its own death and "...'s triggered ability (...)" for the Bears'. Different headings mean the type-ahead is drained between them. The two names come from `TriggerEvent::phrase` (`SelfDies` vs `CreatureDied`) and are deliberate.
- **`--resume` with `--stop-after 1` on a mid-trigger hotseat save.** It answers the pending target prompt as decision 1. With seats overridden to random and no `--seed`, the answer varies from run to run. That is as `--help` describes: the save recorded no rng for its cli seats.
- **`--resume` integrity.** A save with a library id dropped from `library_order` is refused with a named reason, exit 1, before any frame.
