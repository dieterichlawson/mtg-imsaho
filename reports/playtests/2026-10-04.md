## H24 — the schema looser than its parser

Method: every `send_message_structured` caller in `llm.rs`, and the draft
runner's pick and deck schemas, read beside the code that turns the answer
into an action. The question for each: is there a value the schema permits
that the parser changes without a `log_rejected`?

| prompt | schema vs parser | verdict |
|---|---|---|
| action / target / sacrifice pick (`pick_action_index`) | integer `enum`, out-of-range logged and replaced by 0 | sound (the `idx.min(len-1)` after it is dead defence) |
| attackers | per-field enums (#635); out-of-range is logged | **an attacker in both fields: unlogged `retain` → #663** |
| blockers | pairs; illegal, repeated or out-of-range are named and re-asked once, then repaired and logged | sound |
| `mark_indices` / target set | repeats and out-of-range dropped; short of `min` logged | sound |
| card set (bottom / discard) | negatives filtered before the check, but the schema's `enum` + `maxItems` make that unreachable through an enforcing provider | sound in practice |
| ordering | non-permutation logged | sound |
| X funding | string-enum + `required` + `additionalProperties: false`; unreadable values logged (#596) | sound |
| mulligan, concede | missing bool logged | sound |
| **pile division** | inner `pile_a` has no `required`; a missing key reads `false` | **`{}` = everything in pile B, 0 MALFORMED → #662** |
| draft pick / deck | substitution is tracked as `Pick::Substituted`; a bad deck count is an `Err` | sound |

Both findings reproduced in a release build with a stub. Liliana -6 with
`{"pile_a":{}}` logged `pile division: 0 in pile A, 15 in pile B`, with
`grep -c MALFORMED` = 0 and no rejection clause in `TOKEN_USAGE`. Darkthicket
Wolf answering `attacker_indices:[0]` together with
`planeswalker_attacks:[{0,0}]` gave `declared attackers: Darkthicket Wolf
(#14) -> Liliana of the Veil (#64)`, 0 MALFORMED, on seeds 1, 2 and 3. The
engine's own `declare_attackers` would have kept the player attack and
dropped the walker one.

## H23 — the random seat's grouping keys

Run by a subagent with a throwaway `mtg-player/tests` file (since deleted)
that drew `RandomPlayer` 6,000 times over engine-built boards.

- **#664** Loyalty abilities fall to `Decision::Itself`, and the engine emits
  one per target. Garruk Relentless with 8 Bears: fight 0.802, Wolf 0.103,
  pass 0.095. In 40 real games the fight was activated 41 times and the
  Wolf 12.
- **#665** No `ChosenOrder` is ever sent (0 of 6,000), while every other
  surface answers ordering prompts with it. The `choices.rs` arms behind it
  are unfuzzed.
- **#666** Ghoulcaller's Chant: `modal_set` asks "up to 2" from the union of
  both modes' candidates, then refuses any pair that is not two Zombies at
  Debug level. 46% of random answers vanish, and mode two is reached in 1.8%
  of casts. Filed against the engine: a person meets the same silent
  refusal.
- **#667** Copies of targeted spells and of activated abilities are separate
  decisions. Copies of untargeted spells and lands are collapsed. 3 Bolt
  drew 0.605 against 3 Tusker's 0.202.

Checked, correct: the `Ability` and `Cast` keys match the engine's
(including the #610 fix). Every cast-time product now routes through a
prompt. X funding, exile, target set, object set and pile division are all
rolled over their full range. `set_prompt` answers with `min`, which is
latent only while `min == max` in both of today's uses.

## H20 — descriptions that name a permanent, against duplicate names

Run by a subagent: 31 runtime description sites, 18 games and 4 replays,
about 2,670 prompts and 22,300 rows, scanned for byte-identical rows and for
repeated `#id`s in `— one per copy:`. #612, #631 and #634 hold, with 0
repeated ids. The card descriptions are clean now. **The ambiguity has moved
down to the shared label helper:**

- **#668** `obj_name` adds `(#id) (owner)` only to non-land battlefield
  objects. A Maw of the Mire seat picked "0: Mountain", its own land, out of
  two Mountain rows. A Counterspell seat countered its own Dissipate. 104 of
  the 122 duplicate-row prompts were this defect.
- **#669** The CLI half: graveyard target rows carry `(#id)` but no pane
  prints graveyard ids or owners.
- **#670** Skirsdag High Priest is still one row per `C(n,2)` pair: 55 rows,
  then 190 at 20 creatures, which reduce to about 5 real choices.
  `prompt_shapes.rs` cannot see it because the product lives in the cost.
- **#671** doubled stack ownership tags; **#672** stale GAME_RULES
  sacrifice text; **#673** library search lists one row per basic.

Checked, correct: sacrifice slot prompts carry ids. CLI land and stack
targets carry owner tags and ids. Trigger order, damage order and
damage-effect labels disambiguate repeats. The Caravan Vigil and Frightful
Delusion yes/no prompts name exactly one object and cannot be ambiguous.
