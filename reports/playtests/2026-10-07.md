## G26 — the rest of the raw flags (first run)

Every boolean and Option on `PermanentView`, `OpponentView` and `StackItemView` was traced through the four renderers.

**One predicate everywhere** (checked, correct):
- `affected_by_summoning_sickness`, which #604/#605 put in place of the raw `summoning_sick`;
- `tapped`, `regeneration_shields`, `damage_marked`, `attached_to` and `attached_to_player`, `is_token`, `protections` and `restrictions`, and the stack's `x_value` and `source_id`.

## G3 — the prompt with no board (first run)

I staged Nevermore's `ChooseCardName` over a live board with 269 names. The page held up on this prompt:
- The filter box takes focus at once.
- Pages are 20 rows.
- The counter reads "250-269 of 269 (scroll)".
- The last name is reachable in 83 wheel notches.

Keys do nothing to the list — PageUp, Home, End and the arrows — because the field owns the keyboard (#601). So the filter is the only fast route to a name. That is acceptable, given the "Type to filter" hint.

## Process notes

- `pkill -f "gui:8897"` killed its own shell, because the pattern was in the command line. Target a runner by `ps` with a `[m]tg-runner` bracket, never by `pkill -f` on a string the command itself contains.
- `mtg-gui/tests/autoplay.js` spawns `target/debug/mtg-runner` and picks a random port. A patched copy for a release build has to change both. Delete the copy afterwards; it is untracked and the next crew will find it.
