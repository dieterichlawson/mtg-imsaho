# Playtest 2026-10-09 — the harness

Subject chosen from the ledger: the harness had gone longest without a night
(last 2026-10-04; game 10-05, CLI 10-06, GUI 10-07, drafting 10-08). Untried
H ideas were H21, H22, H25-H28. Since the last harness night the seat became
stateless (`MTG_LLM_HISTORY`) and gained the "Pass until something happens"
row (80e0018), so tonight ran H26 and H28 against that new code, plus H21 and
H22. Four probes ran in parallel under stub `CLAUDE_CODE_BIN` seats only. No
metered seat was used, and the real `claude` CLI was not called.

Fifteen issues filed: #743-#757.

## R1 — propagation sweep (issues closed 2026-10-08, #729-#742)

The hosted table (`mtg-draft-server`) is the surface the window's fixes did not
name. #742 (a forfeit is not a concede) reached `mtg-runner`, the page, both game
loops and the engine log, but the table's game page still reads
`GAME OVER! SEAT 1 WINS. / FINAL TURN: 1`. That box has no reason and no
YOU WIN / OPPONENT WINS headline, because `outcomeHeadline` parses only
`Game over! pN` (#743). The view the table sends has no forfeit field, so the
draft page and the client show a stalled seat's loss as a plain 1-0 (#744). Two
smaller ones: the server announces and logs that the draft has started before
it binds its port (#745), and a person whose build timer ran out is logged as
"deck building failed after 0 attempt(s); the runner substituted a deck" (#747).

Checked, correct:
- #740 on the CLI, the page and the random seat.
- #736 on the CLI and the page.
- #738 across 240 random games.
- #741: `#field` is the page's only typed input.
- #735's FATAL reaches the server's log.
- #729-#734 do not apply: the table has no save.

One aside was checked and not filed: a resumed `cc` seat's first prompt carries
the whole game log (~370 lines). That is deliberate (#464 distinguishes the
resume recap from Recent events).

## H21 — the tap plan when mana floats (first run)

The collapse H21 predicted is closed. 40 stub games, 2,299 menus, 3,129 rows
with a tap plan: 0 collide once the clause is stripped, because #611's
`cast_cost_note` puts the cost in every row. The #611 board walked from Red:1 to
Red:6 kept all four flashback rows apart on the seat and in the CLI. Floating
mana merges per-copy rows into one `— one per copy` row with an index per copy,
which is harmless. The random seat and the page key on ids, so they are
unaffected.

Found: since #668 the seat's plan names every land by id and can never group,
while GAME_RULES still documents `(tap 2x Forest)` and its test checks
hand-written strings (#746).

  "Sorcery speed" is matched in the description text.

  Bolts died through four combats.
- **#753** (the page): `f` pressed at upkeep passes the whole turn. #45's CLI fix
  never reached the page.
- **#756:** the row's stop list disagrees with the code.

Checked, correct:
- 0 calls with nothing to do.
- Every stop line and Recent events after a stretch.
- The draft runner's seats get the row.
- A resume clears a stretch.
- The CLI's auto-pass loses nothing the seat keeps.
