# Playtest night — 2026-09-09

**Subject**: drafting (`mtg-draft-runner`), chosen from the ledger rather than
from memory. Drafting and the harness were tied for longest without a night
(both 2026-09-04), and drafting had six never-run ideas to the harness's two:
D4, D6, D8, D9, D10 and D11 had never appeared in a ledger row.

**Crew**: 3 probes — D9 (Operator), D4 (Rules Lawyer), D10 (Operator) — two of
them run in parallel as subagents on their own tmux sockets.
**Runs**: ~26 draft runs through the real binary plus library-level sweeps of
several hundred thousand packs. Every run passed `--model cc` explicitly;
**no metered API seat was spawned at any point**, and the only backend any run
reached was a local stub.
**Issues**: 5 filed — #400, #401, #402, #403, #404.

The night's shape: one probe found a distribution that disagrees with its own
documentation, and two found the same thing in different places — **a path that
does the right thing and forgets to say so, or says something a reader will
believe and that is not true**. That is the failure mode this subject was
warned about ("the correctness questions here are mostly about *silence*"), and
four of the five issues are instances of it.

## The three that matter

**#402 — the same `--seed` deals a different opening hand every run.** The
draft half is perfectly reproducible: three runs of `--seed 41` gave identical
packs, picks, pools and decks. The tournament half is not. `to_decklist`
accumulates the maindeck into a `HashMap` and returns `counts.into_iter()`,
and `DraftDeck.lands` is a `HashMap` too, so the entry order handed to the
engine is `RandomState`-randomized per process. `setup_game` builds
`library_ids` by iterating those entries in order and *then* applies the
correctly-seeded shuffle — shuffling a differently-ordered list each time.
`play_match`'s own comment claims reproducibility as a property of #212's fix.
The log cannot rescue it either: the `DECK` entry is alphabetised, so the
shuffled order is recorded nowhere. This one undercuts every seeded draft
comparison anyone has run since #212 landed.

**#401 — `--resume` erases the picks it replayed.** The replay branch
`continue`s past `log_draft_pick!`, the `substituted_picks` counter and
`write_snapshot`. A run whose 20 snapshot picks were *all* runner
substitutions, resumed with a healthy CLI, finishes exit 0 with no
`Substituted Picks` section at all, zero substitution warnings, 64 `PICK`
lines for an 84-card draft, a full `DRAFT POOLS` section listing cards no log
line records anyone picking, and nothing anywhere saying the run was resumed —
the single notice is stderr-only and `--quiet` suppresses it. #195 exists
precisely so a substituted pick cannot pass for a drafted one; `--resume`
undoes it.

**#404 — a hung `claude -p` never unblocks a draft.**
`mtg-draft-runner/src/llm_client.rs` is a 2026-09-04 copy of the game
backend. Commit 85c38a3 fixed #203/#206 on 2026-09-05 and touched only
`mtg-player/`. The two copies have now diverged **in both directions**, which a
symbol count makes plain:

```
                   draft copy   game copy
setpgid                     0           4
kill_group                  0           4
LiveGroup                   0           4
recv_timeout                0           1
call_timeout                0           2
RETRY_BUDGET                8           0
```

So #218's wall-clock retry budget exists only in the draft copy (which is why
#399 exists), and #203/#206's working timeout, process group, signal handlers
and workdir sweep only in the game copy. Observed at t=327s, past the nominal
300s timeout: the stub wrapper is a killed, unreaped zombie, its `sleep` is
reparented to init still holding stdout, and the runner is still blocked with
its log frozen at the last successful pick and *zero* `API_ERROR` entries.
`MODE=exec`, where nothing survives the kill, times out correctly at 301s,
which pins the cause to reading stdout to EOF and killing only the direct
child. SIGTERM additionally orphans both seats' subprocesses and leaks their
scratch directories.

## The other two

**#400 — an odd `--players` pod opens the wrong mix.** See D9 below.

**#403 — a DFC named `"Front // Back"` lands in the maindeck *and* the
sideboard.** `validate_deck` strips `" // "` in the pool census and the
maindeck check but not in the sideboard subtraction, which compares the pool
card's front face against the raw maindeck string. Result: 23 maindeck + 20
sideboard = 43 cards out of a 42-card pool, both seats, exit 0, no warning.
Filed with honest confidence: the mechanism is confirmed by running it, but
`deck_schema_for` keys the maindeck on front names with
`additionalProperties: false`, so a schema-obedient model cannot currently
emit the input that triggers it. `fallback_deck`, however, emits pool names
verbatim and produces these strings with no stub at all.

## D9 — pod-size fairness (Operator)

**Verdict: the per-seat question passes at every pod size; the pod-wide one
does not.**

#202 found that `is_c1` and `use_rare_sheet1` both key off `pack_index % 2`
while packs were dealt with `i % pod_size`, locking every seat in an even pod
to one parity — half of them could never open a mythic. The fix shuffles the
box before dealing. D9 asked whether that generalizes.

It does, for seats. Sweeping `--players` 2 through 8 over 400 drafts each
(1,200 packs per seat), **no seat was locked to a rare sheet, a common run, a
mythic or a foil rate at any pod size**. Every per-seat tally sits inside
sampling noise of every other.

The residue is one level up. `CollationState::new_random` randomizes all nine
sheet cursors but hard-codes `pack_index: 0`, and `generate_draft_packs` makes
`pod_size * 3` packs. For an odd pod that is an odd number of packs, so a box
that always starts at index 0 contains exactly one more even-index pack than
odd-index — `ceil(3n/2)` of `3n`. The shuffle decides *which seat* gets the
surplus, which is why the per-seat check passes, but cannot change that the
box has one.

All 15 ISD mythics sit on rare sheet 1 and nowhere else, so the surplus lands
on the mythic rate. Measured over 3,000 drafts per pod size, the C1-type
fraction matches `ceil(3n/2)/3n` to four decimals at every size — deterministic,
not noise:

```
pod | packs | C1 frac | expected | mythic rate
  2 | 18000 | 0.5000  | 0.5000   | 12.506%
  3 | 27000 | 0.5556  | 0.5556   | 14.078%
  4 | 36000 | 0.5000  | 0.5000   | 12.572%
  5 | 45000 | 0.5333  | 0.5333   | 12.933%
  6 | 54000 | 0.5000  | 0.5000   | 12.381%
  7 | 63000 | 0.5238  | 0.5238   | 13.176%
  8 | 72000 | 0.5000  | 0.5000   | 12.811%
```

`--players 3` opens mythics at 14.08% against the 12.4% `docs/isd-booster-collation.md`
states, a 13.6% relative inflation, with the C1 commons over-represented in the
same proportion. The doc's per-card equal-frequency claim is explicitly
"compensated by the 50/50 sheet alternation" — an odd pod does not get 50/50.

Two confounds were ruled out rather than assumed. The `pod 8` reading of
12.811% above is seed noise: five independent seed bases scatter it around the
expected 12.397% in both directions (`12.387 12.333 12.519 11.906 12.810`),
whereas the odd-pod figures cannot move, since the fraction driving them is
exact. And `filter_implemented`, which the runner applies before building
sheets, currently removes **0** cards — every ISD card is implemented — so the
library-level sweep and the runner's real path are identical. The `--players 3`
repro was then run end to end through the real binary with a stub seat to
confirm odd pods are reachable at all: no parity restriction, `pod * 3` packs
logged.

Filed **#400**, with the severity flagged honestly — it does not affect
fairness *between* seats, and the default `--players 8` is unaffected. It
matters for odd pods and for anyone treating this generator's output as the
distribution the doc advertises.

## D4 — deck legality and identity (Rules Lawyer)

**Verdict: legality and identity hold; reproducibility does not.**

Twelve runs at `--players 2 --best-of 1`, with a stub answering picks, deck
builds and game decisions deterministically so an exact maindeck could be
forced.

The legality half passed everywhere it was pushed. Every rejection path fires
with a message a model could act on — `'Abattoir Ghoul' is not in your drafted
pool.`, `'Ambush Viper' appears 2 time(s) … only drafted 1`, `Deck has 6 cards
(need at least 40)`, `'Nephalia Drownyard' is not a basic land.` — and each
was followed by the documented 10 retries and then the fallback. Basics come
from a separate map and are never drawn from the pool.

Identity, in the sense D4 asks about, also held: in every run the `[Seat N]
DECK` log entry and the decklist the tournament actually handed the engine
matched card for card including basics, and both seats opened at 33 library +
7 hand. No card was silently dropped — `CardRegistry::get_id_by_name` falls
back to the front face, so even a `"Front // Back"` string resolves rather
than panicking in `setup_game`. A seat answering with just the front name gets
both faces in its decklist and a castable card.

The fallback's honesty is already fixed by #200 and was not re-filed: the
header reads `DECK (40 cards, FALLBACK after 10 failed attempts)`, a `WARN …
the runner substituted a deck` line precedes it, and an `=== Substituted Decks
===` block reaches stderr even under `--quiet`.

What broke was one level beneath "identical": the decklist is the same *set* of
cards every run but not the same *order*, and that is what the shuffle
consumes (#402). #403 came out of the DFC lead the probe was given to confirm
or refute — the lead was correct about the mechanism and wrong about how
easily a real model reaches it, and the issue says so.

Three things were found by reading and deliberately **not** filed, because
they could not be triggered: `parse_deck_response` expands `{name: count}`
into `count` pushed strings before any validation, taking `u32::MAX` on
overflow (a hallucinated 4e9 would allocate ~100 GB, but the enum-constrained
schema prevents it today); a deck with zero basics is rejected outright, so a
legal all-spell limited deck cannot be built (probably deliberate); and a DFC
in a played decklist is shown to the seat under two different names in one
conversation, which `mtg-engine/src/invariants/objects.rs` explicitly
tolerates. The third became a note on #403 and idea D16 rather than an issue.

## D10 — operator failure handling mid-draft (Operator)

**Verdict: #218 is fixed; the hang case and the resume path are not.**

Fourteen runs at `--players 2 --best-of 1`, seeds 1001/2002/3003, with a
counter-driven stub that succeeds for N calls and then fails a chosen way.

The things #218 was filed about are genuinely fixed. Every non-hang failure —
non-zero exit, `is_error`, raw non-JSON, valid JSON with no structured object
— ends in one operator-legible line naming the seat, the pack and the pick
(`Error: seat 0 could not make pack 1 pick 6: claude -p draft seat gave up
after N attempts over Ms`), exit 1, no panic, no backtrace, no `Any { .. }`.
The retry threshold behaves: a single transient failure is absorbed and the
resulting draft is byte-identical to the control, while a permanent one dies
after about nine minutes per the `RETRY_BUDGET` rationale.

Checkpointing works and lands on the *same* position, not a plausible one: a
run that died at pack 1 pick 6 left a 10-pick snapshot, and resuming it
produced a pick list byte-identical to the uninterrupted `--seed 1001` run.
#195's substituted-pick reporting is also intact on the happy path — 74
out-of-range picks produced 74 `WARN` lines and a `=== Substituted Picks ===`
summary naming both seats, so D2 had nothing to add.

The two failures are the ones the probe was told to look for. A hang does not
time out if anything survives the kill (#404), and the resume path launders
its own history (#401). The hang case is worth restating because it is easy to
misread as flaky: with `MODE=exec`, where the stub is the only process, the
timeout fires correctly at 301s; with a backgrounded descendant holding
stdout, the run was still blocked when killed externally at 600s. The
difference between those two runs is the whole bug.

## What the night says about the subject

Three probes, three different corners, and the same shape in four of the five
issues: the program did something in place of what it could not get, or in
place of what it had already done, and the record does not say so. #401
launders substituted picks into drafted ones. #402 lets a seeded run present
itself as reproducible when only half of it is. #403 double-counts a card and
exits 0. #404 blocks forever while its log looks merely idle.

The one issue that is not about silence, #400, is about a distribution
disagreeing with the document that defines it — which is the other method the
README recommends, and the only reason it was found is that D9 asked for a
sweep across *all* pod sizes rather than the pod size the default uses.

Worth recording for whoever picks this subject next: the `CLAUDE_CODE_BIN`
stub is the single most productive tool on this subject. All five issues came
from runs where the "model" was a shell or Python script answering
deterministically. It costs nothing, spawns no metered seat, and makes the
failure modes that matter here reachable on demand.
