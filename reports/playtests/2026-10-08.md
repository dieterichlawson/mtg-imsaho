## D25 — the snapshot's shape (first run)

**The picks half holds.** About 30 corruptions were tried. Each was either refused with a message naming the record, or replayed the identical draft. That covers: a seat past the pod; a pick of -1, 0 or 15; round 4; duplicates; shuffled order; pack 2 started early; edited players/seed/set; truncated, empty and whitespace-only files. #655 and #656 hold. On a clean resume, the header, the "Replaying N" line, the summary and the PICK lines agree on the count.

**What surrounds the check does not hold:**

- **#733.** The replay writes `--save` after every step, before the impossible-card check reaches the bad step. `--resume X --save X` therefore cuts the file to the 18 picks before the bad one. The next resume re-asks 22 picks that were already paid for, with exit 0.
- **#732, the night's worst find.** It needs no corruption at all. A resumed run carries its finished matches but never writes them, so its `--save` holds **zero matches** until it plays one of its own. Resuming a *finished* 4-seat save writes a save with 0 matches. Interrupting a resume during the next live match loses every carried match, and the following resume re-plays and re-bills them. I reproduced this independently with the D26 stub.
- **#734.** `"players": 0` in a save panics (exit 101), while `--players 0` on the command line is refused cleanly.
- **#735.** A refused resume's log header says "(40 picks replayed)", and no `die` ever reaches the log.

Unknown fields and a `version: 99` are accepted silently. That is harmless today, and it is recorded in the guide as a note rather than filed.

## D26 — the tournament half of the snapshot (new)

The source of this idea: `DraftSave` gained `decks` and `matches` with #581. `check_snapshot_shape` only checks `picks`, and the save has no `best_of`. Each was confirmed under a stub that fails every deck build, so the runner substitutes decks and a 4-seat best-of-1 run takes about 40 s:

- **#729.** `--best-of` is taken from the flags. A best-of-1 save resumed at `--best-of 3` (3 is also the default) carries its 0-1 results into a "best-of-3" header and plays round 2 at three games, with exit 0. Seed, set and players each get a `note:`; best-of gets nothing.
- **#730.** Saved decks skip `validate_deck`. A 30-card deck with four Bloodline Keepers the seat never drafted plays the whole tournament. A name that is not a card panics a match worker partway through.
- **#731.** Match records are trusted:
  - A 7-0 result in a best-of-1 is carried as "8 game wins".
  - A record with its seats swapped is dropped, and that match is re-played live with no message.
  - A round-9 record is ignored, and it is gone from the next save.

## Notes for the next crew

- The draft runner must be run from the repo root, because it reads `data/sets/isd.json` relative to the current directory.
- A stub that answers every deck call with `{}` makes the runner substitute a deck after 10 tries, about 20 s per seat in parallel. That is the cheapest way to reach the tournament.
- A stub that picks the action index by regex for `N: Concede` matches the *system prompt's* example ("5: Concede") and returns an out-of-range index. Read only the user message, or let the harness fall back.
