## D16 — one card, one name, all the way down (negative)

The idea, from #403: force the deck-build fallback on a seat whose pool
holds a DFC and read the whole game as that seat sees it — decklist
section, hand, board, event log, every prompt that names a card, and the
response schemas keyed by card name — and verify the seat is never shown,
nor asked to answer with, two different names for the same physical card.

**Set-up.** A `CLAUDE_CODE_BIN` stub that writes every call's argv, stdin
prompt, `--json-schema` and `--system-prompt` to four files, picks a pack
row whose card line names two faces when one is offered, and answers the
deck prompt with `{"thoughts": …, "lands": {"Island": 9}}` — no `maindeck`
key, so `parse_deck_response` refuses all ten attempts and both seats take
the fallback. ISD, `--players 2 --best-of 1 --seed 7`. Two runs: one with
valid decks as a control (680 calls), one forcing the fallback (1,206
calls). Both seats' 42-card pools held three DFCs; Seat 0's fallback deck
maindecked all three (Ulvenwald Mystics, Thraben Sentry, Mayor of Avabruck).

**The answer is that the name chain holds, on every surface, end to end.**

- **0 raw `Front // Back` strings** anywhere a seat or a reader can see
  them. Checked by extracting all 20 full DFC names from
  `data/sets/isd.json` and searching all 1,886 captured prompts, all 1,886
  schemas, all 1,886 system prompts and both run logs for exact
  occurrences. None.
- The only ` // ` a seat meets is the deliberate two-face headline —
  `Ulvenwald Mystics {2}{G}{G} | Creature — Human Shaman Werewolf 3/3 //
  Ulvenwald Primordials 5/5` — and it is byte-identical in the pack line,
  the pool listing and the deck-build prompt, because all three go through
  `card_lines.rs`.
- `deck_schema_for` keys `maindeck` by **front face only**, nested under
  `maindeck` so the #398 rule holds; 0 illegal top-level keys across the run.
  A seat answering with the back face (`"Howlpack Alpha"`) is refused
  correctly with `'Howlpack Alpha' is not in your drafted pool.`
- Both producers of a `DraftDeck` front-face the maindeck now
  (`deckbuilding.rs:193` in `fallback_deck`, `:440` in `validate_deck`). The
  **sideboard** does keep raw pool names in the struct, but `draft_log.rs:282`
  front-faces it on the way out, so the raw string reaches no reader.
- The `--save` snapshot holds raw set-data names (6 of them at seed 7).
  That is the pool's native form, it is internally consistent, and
  `front_face` normalises on read. **Checked, correct** — not filed.
- The seat can *connect* the two names when a card transforms: its decklist
  section carries both faces with both faces' rules text, and the event log
  writes `Ulvenwald Mystics (#1) transforms into Ulvenwald Primordials (#1)`
  with the **same object id on both sides** (#500's fix), 42 such lines in
  the fallback run.
- And the deck the tournament plays is the deck the log says was built: the
  two distinct `## Your decklist` sections appearing across the 1,102 game
  system prompts match the two logged 40-card fallback decks entry for
  entry, 40 of 40 each, with the other seat's differing in 49 entries.

Nothing was filed from D16. The one thing it *did* turn up, off-idea, was a

## D22 — the tournament phase as a concurrency surface (#586, #587, #588)

The idea's premise: every previous draft probe ran `--players 2`, where the
tournament is one match on one thread and nothing is concurrent. At
`--players 8 --best-of 3` a round is four `play_match` threads and four
simultaneous `claude -p` children on top of the eight the draft already
spawns.

**Set-up.** A schema-walking stub (a pure function of prompt‖schema, with a
real permutation for `order` and a concede branch to keep games short),
plus modes for a game call that sleeps with a `sleep` **descendant holding
its stdout** and for one seat's calls to fail permanently. Nine eight-seat
runs, two four-seat runs, ~7,000 stub invocations.

**The concurrency itself is sound.** Five things checked and correct:

1. **Signals reach the tournament's children.** `SIGINT` during round 1 with
   four matches in flight killed all four stubs *and* all four `sleep`
   descendants — 0 orphans. The game backend's children are in the same
   `LIVE_GROUPS` the draft's are, so #538's fix covers the phase it was not
   written for.
2. **No block interleaves.** Across 12 matches and 31 games at 8 seats,
   every `MATCH Round N` line and every `GAME n` block is contiguous; they
   are written from `main` after the join.
3. **The usage counters survive four match threads exactly.** The stub was
   invoked 936 times (344 draft + 592 game), 117 of those failed, and the
   run printed `Games: 475 calls` — 592 − 117, to the call.
4. **A match's fatal is not swallowed by the join order.** #539's defect
   does not apply here: the tournament workers go through `in_seat`, which
   reports from the failing worker rather than from the join.
5. **The scratch sweep covers both prefixes**, and stale
   `mtg-draft-claude-code-*` directories left by a signalled run are gone
   after the next run's `prepare_seat`.

**What broke is the bookkeeping around it.**

**#586 — the same `--seed` writes two different logs again.** `buffer_here()`
is installed on the deck-build scope (`main.rs:880`) and the tournament
scope (`:994`) and **not on the pick loop**, and #542's fix added a `SESSION`
record written from inside the pick worker at `llm_client.rs:768`. So the
one block of lines that escapes #541's determinism machinery is the
per-seat session ids. Two runs each of `--players 8 --seed 7` and
`--seed 41` (114k and 119k line logs) give 4 and 3 ordered diff hunks with
an **empty sorted diff** — the signature of an ordering defect, not a
different run — and every hunk is the same eight `SESSION` lines. Confirmed
again at `--players 4 --seed 3`. This is invisible at `--players 2`, where
the block is two lines and falls the same way about half the time: D12's own
warning landing on the fix that came out of it.

**#587 — a dead subprocess is reported as a model that answered `{}`.** One
seat's backend made to fail for the whole tournament: 40 prompts, 1
answered, 39 substituted. Every one of the 39 is logged as a malformed
*model* answer — `Mulligan response missing 'mull' bool ({}), defaulting to
keep` — immediately after `claude -p exhausted all 3 attempts`, and the
end-of-run block counts them under the same words a hallucinated index
gets. The operator cannot tell "your CLI is broken" from "the model is
playing badly", and in a mixed run the two are added into one number.
Measured, the whole retry window for a decision is **≈6.5 seconds**
(241ms + 2s + 238ms + 4s + 240ms), against the draft backend's 600s budget
next door — the divergence #399 asked to be closed and whose close took only
the counting half. D14 measured the same divergence independently from the
other end; its numbers are on #399 and cross-referenced from #587.

**#588 — the standings row does not carry the qualifier.** The runner has
four facts meaning "rank this seat, but the result is not wholly its own"
and prints them four ways: a bye inline (`[1 bye]`, #486), a substituted
deck and a forfeited game each in their own `=== … ===` section, and
substituted *answers* inside `=== Token Usage ===`. In the #587 run the row
printed first is `1. Seat 1 — 3-0 (6 game wins)` for the seat that answered
one of its forty decisions; the qualifier is eleven lines below under a
heading about tokens. Filed as a presentation judgment with the severity
said honestly — #489 chose the block deliberately, so this may be settled
and closable without ceremony.

## D14 — subprocess-lifecycle parity between the two `claude -p` backends (#583, #584, #585)

One stub with fourteen modes driven through **both** backends — exit 7,
`is_error`, junk stdout, empty stdout, hang-with-descendant, hang-with-`exec`,
answer-then-linger on stdout and on stderr, a result with no
`structured_output`, a 20-second transient outage, and SIGINT/SIGTERM/SIGHUP
including one delivered during a draft's *tournament* phase. ~36 runs across
two binaries, ~2,300 stub invocations, `ps` snapshots after every mode.

**The process half is in parity and clean.** The per-call timeout fires at
the configured value on both (`5001ms`/`5002ms` at
`MTG_CLAUDE_CODE_TIMEOUT_SECS=5`), the wording of every non-fatal line is
identical apart from the deliberate `attempt 1` vs `attempt 1/3`, all three
signals exit 130/143/129, and there were **zero orphaned stub processes or
descendants on either side in any mode**. `claude_code_run` being one shared
function did its job; #404 is genuinely closed. Also checked and correct:
`Drop` removes the workdir on both, #540's relative-path resolution works on
both, the missing-binary refusal is identical, and
`MTG_CLAUDE_CODE_TIMEOUT_SECS` reaches both.

**The reporting half is not**, in three new places. `API_RETRY` is written
at `INFO` by `claude_code.rs:447` and at `ERROR` by `llm_client.rs:750`, so
`grep ERROR` over a game log finds no usage-limit retry (#583). The draft's
fatal prints the configured budget where the elapsed time belongs — *"gave
up after 1 attempts over 6s"* after 60 seconds (#585). And the biggest find
was not on the idea's mode list at all: **`available()`'s `--version` probe
is the only `claude -p` subprocess outside the watchdog** — no timeout, no
`setpgid`, no `LIVE_GROUPS` slot — so a CLI that does not answer `--version`
hangs **both** runners forever before the first prompt with no message, and
a signal leaves the probe and its descendant at `PPID=1` (#584).

The retry policy is still #399's deferred judgment call, now with a number:
a 20-second outage costs the game seat **2 of 74 decisions** to the fallback
and the draft seat **none**, and a call that *succeeds* with prose and no
`structured_output` gets 0 retries from the game copy against
retry-then-fatal from the draft copy (74/74 decisions substituted, no
stderr, exit 0).

## D13 — what else a resume launders (#578–#582)

Fourteen runs at `--players 2` and `--players 4`, seeds 7/11/23/3, under a
stub with a shared success counter so the calls could be added back up;
failures injected by stub exit and by `SIGKILL` mid-tournament; save/resume
chains of two and three processes.

**#401's fix holds in full** and was verified end to end: the header carries
`resumed from: <path> (N picks replayed)`, all 84 picks come back as
`PICK … — replayed from the snapshot, no prompt sent`, a snapshot holding 20
substituted picks resumes into `=== Substituted Picks === 20 pick(s)` plus
20 `WARN Pack` lines, `--save` keeps writing after a resume, and a resumed
run's snapshot resumes again.

**The laundering moved to the money and the flags.** `print_usage_summary`
is reached only on the happy exit, so `die` and a `SIGKILL` publish nothing
at all, and `MODEL_USAGE` is process-local: one `--seed 7` draft split
across three runs made **288 successful `claude -p` calls and reported 238**,
with the surviving run printing `Draft: 36 calls` into the same file whose
log holds 84 `PICK` records (#578; seed 23 across two runs, 288 real / 248
reported). `DraftSave` records `{seed, set, players, picks}` and the
reconciliation checks exactly those three, so an alpha-guide snapshot
resumed under beta exits 0 with the header asserting `guide: beta.txt` for a
draft 20 of whose picks were alpha's (#579). A resume that grows the pod
pads `guides` with `None` while `models` is padded with `models[0]`, so a
global `--guide` reached 2 of 4 seats (#580); the reconciliation note fires
against the *generated* default seed and announces a 19-digit number nobody
passed (#582); and `--save` checkpoints the pick loop only, so a kill just
inside the tournament re-bills the deck build and every game — 49 of 288
calls bought twice, in the phase that is ~95% of a default run's calls
(#581).

## What the night says about the subject

Three of the four probes found nothing in the *mechanism* and everything in
the *account of it*. The process lifecycle is in parity and orphan-free
(D14); the eight-seat tournament's concurrency, counters, pairings and
signal path are all correct (D22); a card has exactly one name on every
surface a seat reads (D16). What is still wrong, four separate times over,
is what the run tells the operator afterwards: a dead CLI reported as a bad
model (#587), a retry that `grep ERROR` cannot find (#583), a budget printed
as an elapsed time (#585), a cost that cannot be added back up (#578) and a
seed that no longer replays its own log (#586).

That is the shape `drafting.md` already names — *"the correctness questions
here are mostly about silence"* — arriving one layer out from where the guide
puts it. The fallbacks no longer *hide* a substituted decision; they still
mis-describe where it came from.
